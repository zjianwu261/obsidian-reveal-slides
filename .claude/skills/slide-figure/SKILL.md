# slide-figure

给幻灯片课件画图。**你不手写 SVG，你写声明，脚本渲染。**

## 为什么不让你直接画

手写 SVG 每次构图都不一样，一处坐标算错就错位，改配色要动几十行。
而框宽、间距、对齐这类事，本来就该由代码算——同一类图，第 3 页和第 30 页必须长得一样。

所以分工是：**你负责内容（十几行 JSON），脚本负责像素。**
出了问题也一眼看得出是声明写错了，还是渲染器有 bug。

## 最常见的入口：给现成的一页配图

用户通常不会凭空描述一张图——**这一页的文字他早就写好了**。所以默认流程是：
读这一页，把它的结构画出来，再把文字里跟图重复的部分删掉。

**第一步，读两处**：

- `<grid>` 里的正文（要点列表、表格）——这是他准备投出去的内容
- `note:` 后面的讲稿——**信息通常更全**，很多结论、易错点、考题只写在这儿

**第二步，判断画哪种**：

| 这一页在讲什么 | 用哪种 |
|---|---|
| 一件事分几步、或前后两种做法的区别 | `flow` |
| 两三个概念摆在一起比 | `compare` |
| 某个寄存器有哪些位、这节讲哪一位 | `bitfield` |
| 按时间推进的过程 | `timeline` |

拿不准就看正文的形状：并列的三组 → `compare`；带箭头/先后的 → `flow`；
出现 D7~D0、位名 → `bitfield`。

**第三步，画完之后回头改文字**——这一步最容易漏，但决定了一页课件是"图文咬合"
还是"同一件事说两遍"：

- 图已经讲清楚的条目，从正文里**删掉**
- 正文只留图上没有的：结论、易错点、考题、口诀
- 讲稿（`note:`）一个字都不用动，那是讲的，不是投的

**交付时告诉用户三样**：声明文件放哪、```` ```svg ```` 块、以及**建议从正文里删掉哪几条**。
最后一样别省——不说的话，用户会把图直接贴在原文旁边，那就白改了。

## 怎么做

**第一步**：把用户的要求写成声明，存成 JSON 文件。四种 type，格式见下。

**第二步**：调脚本渲染。

```bash
python3 .claude/skills/slide-figure/scripts/figure.py 声明.json -o 图.svg
```

只用标准库，不联网，不需要任何 API key。

**第三步**：把生成的 SVG 包成 ```` ```svg ```` 代码块交给用户，并**保留声明文件**——
下次改图是改 JSON 重渲，不是重新画。

放进幻灯片：

````markdown
<grid dim="60 45" pos="4 18" class="fig">

```svg
（脚本输出的 SVG 原样贴这里）
```

</grid>
````

插件的 `svgProcessor` 会把它渲染成图片，`autoFoldSvg` 会自动折叠这段代码，不撑乱笔记。

## 四种 type

### flow —— 步骤流程 / 前后对比

```json
{ "type": "flow",
  "rows": [
    { "chip": "++b", "steps": ["先自增 +1", "再参与运算"],
      "note_title": "b = 3 时", "note": "c = ++b → 4" },
    { "chip": "b++", "steps": ["先参与运算", "再自增 +1"],
      "note_title": "b = 3 时", "note": "c = b++ → 3" }
  ] }
```

一行一条流程。`chip` 是主体，`steps` 是环节（自动加箭头、框宽按字数算），
`note` 挂在右侧放具体例子。两行之间自动画分隔线。

### bitfield —— 寄存器位分布

```json
{ "type": "bitfield", "name": "TCON", "addr": "0x88", "meta": "可位寻址",
  "bits": ["TF1","TR1","TF0","TR0","IE1","IT1","IE0","IT0"],
  "highlight": ["IT0"],
  "caption": "本节只用 IT0：置 1 = 下降沿触发外部中断 0" }
```

`bits` **高位在前**，D 编号自动标。`highlight` 写位名或位号（`0` 也认），
标出这节课要讲的那一位。`caption` 一句话点题——八位逐个解释是讲稿的事，不是图的事。

### compare —— 两三列对照

```json
{ "type": "compare",
  "columns": [
    { "title": "赋值运算符", "highlight": true,
      "lines": ["`a = a + b`", "先算右边", "再装进左边的变量", "结果是「值」"] },
    { "title": "关系运算符",
      "lines": ["`a == b`", "比较两边", "给 if / while 用", "结果只有真 / 假"] }
  ] }
```

`lines` 里用反引号包住代码，会自动用等宽字体。`highlight` 标出本节主角。
**一列不超过四行**，多了就该拆两页。

### timeline —— 时序 / 阶段

```json
{ "type": "timeline",
  "nodes": [
    { "label": "装初值", "sub": "TH0/TL0" },
    { "label": "启动计数", "sub": "TR0 = 1" },
    { "label": "溢出置位", "sub": "TF0 = 1" }
  ] }
```

`label` 写"发生了什么"，`sub` 写"对应哪个寄存器位"。**节点不超过五个。**

可运行的样例在 [examples/](examples/)，改一改就是新的图。

## 图里的字要和正文一样大

字的最终大小取决于图被塞进多宽的格子——同一张图放进 92% 宽和 55% 宽的 grid，
字能差出一倍。所以：

| 图所在 grid 的宽 | 声明里怎么写 |
|---|---|
| ≥ 88（图占满整行） | 不用管 |
| 50~65（跟正文并排） | 加 `"textScale": 1.6` |

`textScale` 不改字号，改的是画布宽度（900 / scale）。画布窄了，同样的字在最终画面里
就显得大。范围 0.5~3。

## 写声明的几条规矩

- **一张图只讲一件事**。三个概念画三张，别挤成一张。
- **不要在图里重复幻灯片的标题**。标题由页面顶部的标题条承担，图再写一遍就是同一件事
  说两遍——这正是"图文割裂"的来源。
- **文字精炼**。投影上要让最后一排读得清，一个框里塞一行说明就够。
- **一张图最多两个重点**（`highlight`）。全都强调等于没有强调。

## 配色

默认用课程主题的色板（主色 `#064FA1`）。改配色有两条路，都不用碰渲染器：

- 单张图：在声明里加 `"theme": {"brand": "#B81C22"}`
- 整套图：写一份 `theme.json`，渲染时 `--theme theme.json`

可覆盖的键：`brand` `soft` `line` `arrow` `text` `muted` `accent` `rule` `font` `mono`。

课程主题的真值在 `<库>/Extra/SlideCSS/CSS+《单片机原理与应用》课件.md`，
改过配色的话以它为准。

## 脱离智能体单独用（可选）

`scripts/nl2figure.py` 让你在命令行里一句话出图，**任何 OpenAI 兼容接口都行**，
默认走 DeepSeek：

```bash
export FIGURE_API_KEY=sk-xxx
python3 scripts/nl2figure.py "画一张 TCON 的位分布，这节讲 IT0" -o tcon.svg --spec-out tcon.json
```

换供应商就改两个环境变量（`FIGURE_API_BASE` / `FIGURE_MODEL`），或者写进
`config.json`（优先级：命令行 > 环境变量 > config.json）。

**在智能体里不需要它**——你自己就能写声明，直接调 `figure.py` 更快、更省、也更可控。

## 交付前自检

1. 声明存下来了吗？（下次改图靠它，别让用户回头重新描述一遍）
2. 图里有没有重复页面标题？
3. 每个框的文字是不是够短？投影上读得清吗？
4. `highlight` 是不是只标了真正要讲的那一两处？
5. SVG 是不是包在 ```` ```svg ```` 里、放进了 `<grid>`？
