# slide-figure

给幻灯片课件画图。**产出 SVG 源码，不产出位图**——位图投影必糊，改一个字要重新生成整张。

## 输出契约

只输出**一个** ```` ```svg ```` 代码块，别的什么都不要（不解释、不寒暄、不加标题）。用户直接复制粘贴到笔记里的 `<grid>` 中：

````markdown
<grid dim="60 70" pos="4 15" class="fig">

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 900 250" …>…</svg>
```

</grid>
````

插件的 `svgProcessor` 会把它转成图片渲染，`autoFoldSvg` 会自动折叠代码块，不会把笔记撑得没法读。

## 三条硬约束

违反任何一条，图就白画了：

1. **文字必须是 `<text>` 元素，绝不转曲（path）。** 转曲之后不能改字，等于又变回了位图，失去做 SVG 的全部意义。
2. **不引用任何外部资源。** 没有外链字体、没有 `<image href="http…">`、没有 `@import`。图被塞进 `<img>` 渲染，外部资源一律加载不到。
3. **中文字体必须带兜底**：`font-family="-apple-system, 'PingFang SC', 'Microsoft YaHei', sans-serif"`。少了这串，Windows 上会掉成宋体，投影很难看。

另外：`<img>` 里的 SVG 是独立文档，**拿不到页面的 CSS 变量**——`var(--brand)` 在里面是空的，颜色必须写死十六进制。

## 尺寸与字号

- 写 `viewBox`，**不要写 width / height**——让它跟着容器缩放。
- viewBox 的宽高比要贴近它所在 grid 的宽高比，否则图周围会留下大片空白。
- **字号下限：不小于 viewBox 宽度的 2%**（viewBox 宽 900 时，正文 ≥ 20，最小标签 ≥ 18）。教室后排看不清的字等于没写。
- 元素之间留白不小于字号的 0.6 倍，投影上挤在一起的框会连成一片。

## 配色

默认用课程主题的色板。**动手前先读一眼真正的主题文件**（如果找得到），以它为准：

```
<库>/Extra/SlideCSS/CSS+《单片机原理与应用》课件.md
```

拿不到就用这一组：

| 用途 | 值 |
|---|---|
| 主色（重点框、强调字、箭头端点） | `#064FA1` |
| 浅底（主色框的填充） | `#EAF1FA` |
| 次级描边（非重点的框） | `#C9D8EC` |
| 箭头、分隔线 | `#9BB4D4` |
| 正文 | `#1a1a1a` |
| 辅助说明 | `#555` |
| 强调（易错点、结论） | `#8A2B2F` |

**一张图里最多两个重点色块**。全都强调等于没有强调。

## 版式规则

- **图里不要重复幻灯片的标题**。标题由页面顶部的标题条承担，图再写一遍就是同一件事说两遍——这正是"图文割裂"的来源。
- **一张图只讲一件事**。三个概念画三张，别挤成一张。
- 结构化的样式集中写进 `<defs><style>`，用 class；别每个元素堆 `style=` 属性——那样改配色要改几十处。
- 图里的代码、变量名用等宽字体：`ui-monospace, Menlo, monospace`。

## 图型模板

四种覆盖课件里绝大多数场景，代码见 [templates.md](templates.md)：

| type | 什么时候用 |
|---|---|
| `flow` | 步骤流程、前后对比（`++b` vs `b++` 这类） |
| `compare` | 两列对照（赋值 vs 关系运算符） |
| `bitfield` | **寄存器位分布**（TCON / TMOD / SCON，单片机课件的高频项） |
| `timeline` | 时序、阶段推进 |

照着模板改，别每次从零构图——版式稳定下来，学生翻页时的认知负担才低。

## 交付前自检

1. 有没有 `<text>` 被转成 path？
2. 有没有外链？
3. 中文字体兜底写了吗？
4. 最小的字够不够 viewBox 宽度的 2%？
5. 图里有没有重复页面标题？
6. 颜色是不是写死的十六进制（不是 `var(...)`）？
